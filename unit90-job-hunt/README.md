# Unit 90 · 求职投递：跟踪器与漏斗复盘

> 目标：**求职是漏斗，用数据决定「下一个把时间花在哪」。**

---

## 一、漏斗三层

```
投递  ──→  沟通  ──→  面试  ──→  offer
 100       30        10        1
```

| 指标 | 含义 | 低了说明什么 |
| --- | --- | --- |
| 沟通率 | 有多少 HR 愿意聊 | 简历/岗位匹配度有问题 |
| 面试率 | 有多少进面试 | 简历夸大、或渠道质量差 |
| offer 率 | 有多少拿 offer | 面试表达/技术深度不足 |

**每一层的问题，解法完全不同。** 这才是「记录」的意义——不记就不知道该改哪。

## 二、状态只能前进

```python
STATUS_FLOW = ["已投递", "已沟通", "面试中", "已 offer", "已拒绝"]
```

- 状态只能往前走（`已投递 → 已沟通 → 面试中`），不能回退
- **「已拒绝」可以从任何状态进入**（包括拿到 offer 后拒掉）

防止误操作把已有面试记录改回「已投递」，导致统计失真。

## 三、按渠道复盘

同一个岗位，不同渠道的面试率可能差 3 倍：

```json
{
  "内推":      {"total": 5, "interviewed": 4, "interview_rate": 0.8},
  "BOSS直聘":  {"total": 20, "interviewed": 3, "interview_rate": 0.15}
}
```

结论很直接：**内推的转化率是平台的 5 倍**。下次时间该花在找人内推上。

## 六、复盘要记什么（每次面试后）

```
1. 问了哪些题？哪些答得不好？
2. 面试官关注什么？（工程能力 / 算法 / 业务理解）
3. 我讲项目时卡在哪？（大概率是量化数据不熟）
4. 下一场要补什么？
```

## 七、面试追问

**Q: 投多少家合适？**
→ 计划里写「每天投 10 家」，但质量比数量重要。
先精投 5 家（内推/匹配度高），再海投兜底。

**Q: 面试被拒怎么复盘？**
→ 分清「能力不足」和「不匹配」。能力不足要去补（记录下来下次不犯）；
不匹配不要自我怀疑（那是概率问题）。

**Q: 什么时候该停？**
→ 连续 20 家没有面试 → 简历/定位有问题，先改简历；
面试 5 家都没 offer → 面试表达有问题，做模拟面试（Unit 87–89）。
