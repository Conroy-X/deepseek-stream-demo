# project1-ai-chat

一个完整的 AI 对话应用：**FastAPI + PostgreSQL + JWT + SSE 流式**。
90 天转型计划的第一个作品级项目，阶段一的收口。

> 不是 demo：有用户体系、有持久化、有越权防护、有重试与限流、有成本账本。

## 功能

| 模块 | 能力 |
| --- | --- |
| 用户 | 注册 / 登录（Argon2id + JWT），禁用即失效 |
| 会话 | 新建 / 列表 / 删除，首条消息自动成标题，按活跃度排序 |
| 对话 | SSE 逐字流式，支持中断（已生成部分自动保存） |
| 数据 | PostgreSQL 三表 + 外键级联，消息永久留存 |
| 工程 | 超时 / 指数退避重试 / 令牌桶限流 / 成本记账 / 上下文裁剪 |
| 安全 | 越权返回 404、密码不落明文、token 篡改即失效 |

## 架构

```
┌──────────────────────────────┐
│  浏览器 (static/index.html)   │
│  登录 / 会话列表 / 聊天窗口     │
└───────────┬──────────────────┘
            │ HTTP + SSE
            │ Authorization: Bearer <JWT>
┌───────────▼──────────────────┐
│  FastAPI (main.py)           │
│  ├── get_current_user  ← security.py (JWT 验签 + Argon2) 
│  ├── /conversations/{id}/chat │
│  └── StreamingResponse ───────┼──┐
└───────────┬──────────────────┘  │
            │ SQLModel            │ llm_client.py
┌───────────▼──────────┐  ┌───────▼──────────────┐
│  PostgreSQL          │  │  DeepSeek API         │
│  users               │  │  超时 / 重试 / 限流    │
│  conversations       │  │  token 与成本统计      │
│  messages            │  └──────────────────────┘
└──────────────────────┘
```

请求时序（一次提问）：

```
前端               后端                    PG              模型
 │  POST /chat      │                       │                │
 ├─────────────────►│                       │                │
 │                  │ ① 存 user 消息 ──────►│                │
 │                  │ ② 读最近 20 条历史 ──►│                │
 │                  │ ③ 调用流式 ──────────────────────────►│
 │◄─ start ─────────┤                       │                │
 │◄─ delta × N ─────┤◄──────────────────────────────────────┤
 │                  │ ④ 存 assistant 消息 ─►│                │
 │◄─ saved ─────────┤                       │                │
 │◄─ [DONE] ────────┤                       │                │
```

关键点：①② 在返回响应头**之前**完成，④ 在流结束后**自己新开 session** 写库
（请求级 session 此时已关闭）。

## 技术选型与理由

| 选择 | 为什么不选另一个 |
| --- | --- |
| **SSE** | WebSocket 是双向的，这里只要单向推送。SSE 走 HTTP、过代理友好、断线重连现成 |
| **PostgreSQL** | SQLite 单机单进程，多 worker 会 `database is locked`；PG 还顺带能装 pgvector 做阶段二 |
| **JWT** | 无状态、多实例友好。代价是不能主动吊销，所以 access token 设短 |
| **手写重试** | SDK 自带重试会和自己的重试叠乘（3×3=9 个请求），重试只能有一层 |
| **滑动窗口裁剪** | 简单可预测、成本有上界。摘要压缩要多一次 LLM 调用，RAG 属于阶段二 |
| **Argon2id** | bcrypt 有 72 字节截断、无内存硬化；passlib 已停止维护 |

## 快速开始

```bash
# 1. 数据库（本机已有 PG 则跳过）
docker compose up -d          # 映射 5433，避开本机 PG 的 5432

# 2. 依赖与环境
uv sync
cp .env.example .env
#   - DEEPSEEK_API_KEY 填真实 key
#   - JWT_SECRET 用下面命令生成
python -c "import secrets; print(secrets.token_urlsafe(48))"

# 3. 启动
uv run uvicorn main:app --reload --port 8000
```

打开 <http://127.0.0.1:8000/>，注册 → 登录 → 新对话 → 开聊。

## 自检

```bash
uv run python main.py
```

23 项，用假 LLM，**不花钱、不联网**：认证、越权、流式事件、落库顺序、
自动标题、上下文裁剪、报错降级全部覆盖。

## 已知限制（主动说出来，比被问住强）

- **JWT 无法主动吊销**：access token 有效期内一直能用。生产要配 refresh token + `jti` 黑名单
- **限流是单机内存版**：多实例部署会失效，需换 Redis
- **没有真正的"停止生成"按钮**：前端只是断开连接，后端在 `is_disconnected()` 处 break，
  模型侧可能仍在计费几秒
- **上下文只做滑动窗口**：会忘掉早期对话，阶段二的 RAG 解决这个问题
- **无 Alembic**：`ensure_schema()` 是手工幂等迁移，字段一多就该换工具
