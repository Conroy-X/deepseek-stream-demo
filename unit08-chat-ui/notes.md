## 渲染 Markdown 的 6 个坑

### 1. 顺序：先转义，再替换

```
❌ 先替换 **粗体** 再 escapeHtml → XSS 风险
✅ 先 escapeHtml，再替换
```

### 2. 行内代码要提前「占位」

`**` 如果出现在 `` `code` `` 里，不能被当成加粗。
做法：先把行内代码抠出来存成占位符，最后再还原。

### 3. 链接只允许 http/https

```javascript
/\[([^\]]+)\]\((https?:\/\/[^\s)]+)\)/g
```
不加限制的话 `[点我](javascript:alert(1))` 就是 XSS。

### 4. 代码块用状态机，不用正则

```javascript
if (fence) inCode = !inCode;      // 遇到 ``` 翻转
if (inCode) { codeBuf.push(line); continue; }  // 代码块内不解析任何 Markdown
```

### 5. 未闭合的代码块不能丢

流式输出到一半，```` ```python ```` 后面的内容可能还没到。
如果丢弃，用户会看到内容凭空消失。

### 6. 复制按钮用事件委托

消息是动态插入的，逐个绑事件会内存泄漏。
在父容器绑一次，用 `e.target.closest(".copy-btn")`。

## 流式渲染的性能

逐字符 `innerHTML = renderMarkdown(raw)` 会很卡。

当前做法：
- 每收到 delta 就重渲染整段（简单、可靠）
- 用 `requestAnimationFrame` 节流滚动

优化方向（以后）：
- 只在「结构性 token」到达时重渲染（`\n`、```` ``` ````、`|`）
- 或改用 diff 更新

## 面试追问

1. **「前端渲染 Markdown 有什么安全风险？」**
   → XSS。必须转义原始 HTML，限制链接协议，代码高亮库也要注意别引入 `dangerouslySetInnerHTML` 的漏洞。

2. **「流式渲染 Markdown 有什么难点？」**
   → 内容不完整。可能收到半个代码块、半个表格。要能容忍「未闭合」状态，
   并且不能因为解析失败就丢内容。

3. **「怎么做代码高亮？」**
   → 生产用 Shiki / highlight.js / Prism。本单元为了零依赖手写了一个极简词法高亮，
   只识别关键字/字符串/数字/注释/函数名。
