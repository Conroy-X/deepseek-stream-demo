## 实测（本单元最重要的数据）

内置语料 6 个话题、49 句、约 1700 字，12 道固定问题，`size=160 / overlap=30 / top_k=3`：

| 策略 | 块数 | 平均字数 | 命中 | recall@3 |
| --- | ---: | ---: | ---: | ---: |
| fixed | 10 | — | 11/12 | **0.92** |
| recursive | 10 | — | 12/12 | **1.00** |
| semantic | 18 | — | 12/12 | 1.00 |

fixed 丢的那一题，是因为句子被从中间切开：「退款多久到账」的答案跨在
两块的交界上，两块各带半句，谁都不够像。

> 数字会随 `size` 变。想验证"size 影响命中率"，把 slider 从 160 拉到 400 再对比一次 ——
> 块越大，混进来的话题越多，向量被平均，命中率反而掉。

## 三个实现细节（都是坑）

**1. `overlap >= size` 必须直接报错**

不是保守，是死循环：`step = size - overlap = 0`，切分永远前进不了。

**2. 覆盖率要用"去重"算法**

`sum(len(chunk))` 在有 overlap 时必然大于原文，看不出是否丢字。
正确做法是打一个字符掩码，看原文每个位置有没有被至少一块覆盖：

```python
mask = bytearray(total)
for c in chunks:
    for i in range(c.start, c.end):
        mask[i] = 1
return sum(mask) / total      # 必须是 1.0
```

**3. 小标题不能孤立在块尾**

凑长度时，`费用报销与差旅` 这种短标题会刚好塞进上一块的末尾，
于是它挂在一堆年假条款后面 —— 检索时它谁也不代表。
所以切分前要先把标题粘到它的正文上，且给正文留出 `size - 标题长度` 的额度。

## 语义切分的阈值为什么是 0.05

因为**阈值跟模型绑定**。本地哈希向量下，本单元 49 句的相邻相似度：

```
中位数 0.096 · 最大 0.381
```

阈值取 0.3 会把 49 句切成 48 块（等于逐句切），取 0.05 才是 18 块。
换真语义模型（中位数通常 0.4 以上）必须重新标定 —— 抄别人的 0.8 等于没做。

> 自检会打印这行数字，`uv run python main.py` 自己看一眼。
