# Unit 70 · Evaluation：30 条评测集 + 四项指标

> 目标：**建 30 条评测集，跑检索命中率 + 忠实度 + 答案相关性 + 拒答双侧。**
> 这是 RAG 的「体检报告」，每次改 prompt/检索/模型都要重跑。

---

## 一、评测集设计（30 条）

| 类别 | 条数 | 说明 |
| --- | --- | --- |
| 退款类 | 6 | 到账时间、未发货、虚拟商品等 |
| 年假类 | 5 | 天数、申请流程、审批人 |
| 病假/报销 | 6 | 证明、时限、住宿标准 |
| 安全类 | 5 | 密码策略、数据导出 |
| **应拒答** | **8** | 知识库里**没有**的（天气/股价/CEO/食堂等） |

**应拒答的 8 条是最容易被忽略的**：只评测「能答的」，永远发现不了「乱答」。

## 二、四个指标

| 指标 | 衡量什么 | 怎么算 |
| --- | --- | --- |
| **Recall@K** | 检索有没有找到该找的 | gold 文档是否在 top-k |
| **忠实度 faithfulness** | 答案是否来自检索结果（防幻觉） | 答案实词有多少落在上下文里 |
| **答案相关性 relevance** | 答案是否真的回答问题了 | 问题关键词在答案里的覆盖率 |
| **拒答双侧** | 该拒的拒了 / 不该拒的别拒 | 混淆矩阵 |

## 三、为什么忠实度这么算

```python
def faithfulness(answer, contexts):
    ans = re.sub(r"\[\d+\]", "", answer)     # 去掉引用标记
    ctx_chars = set("".join(contexts))       # 上下文的字符集
    meaningful = [c for c in ans if 是实词]
    return 命中数 / 实词总数
```

**字符级**是简化版：真实场景用**句子级**（答案每句是否能在某段上下文里找到支撑）
或 **NLI 模型**判断「上下文是否蕴含这句话」。

但字符级已经能抓到「答案里出现资料中没有的词」——这就是幻觉的第一信号。

## 六、面试追问

**Q: 评测集怎么建？**
→ 真实日志采样 + 人工标 gold；要覆盖正常问答、拒答、难例（改写/多跳）。
规模不用大，100–200 条就能发现问题；关键是**每次改动都重跑**。

**Q: 忠实度和相关性有什么区别？**
→ 忠实度看「答案有没有脱离资料」（防幻觉）；相关性看「答案有没有回答问题」（防答非所问）。
一个答案可以既忠实（照抄资料）又不相关（抄了无关段落）。

**Q: LLM-as-judge 和规则指标怎么选？**
→ 规则指标快、可复现、便宜，适合 CI 里每次跑；
LLM-judge 能评「语义好不好」，但有偏差且贵，适合定期抽检。
两者配合：规则守底线，judge 看上限。
