# Unit 21 笔记 · Citation 引用校验

> 引用的价值不在「显示了几个角标」，而在「点下去能不能落到原句」。

## 本次做了什么

- 写了 `citation.py`：`extract_refs`、`split_sentences`、`support_score`、`locate`、`validate`、`render`、`highlight`。
- 写了 `main.py`：6 个内置案例 + 6 个路由 + 64 条离线自检。

- 跑通 `结果：64 通过 / 0 失败`，全部离线，不依赖任何模型。

## 一、什么才算引用：正则必须限位

`CITE_RE = re.compile(r"\[(\d{1,2})\]")` —— 只认 1 位和 2 位数字。

实测：`extract_refs("自 [2026] 年起") == []`，`extract_refs("见 [123] 号文") == []`，
`extract_refs("甲[1]乙[2]") == [1, 2]`，`extract_refs("甲[1]乙[1]") == [1]`（去重但保序）。

为什么限位这件事值得单独写一段：中文技术文档里 `[2026]` 是年份。放宽成 `\d+` 之后，
每一篇带日期的文档都会产生一堆「引用了不存在的来源 2026」，然后所有人学会无视这条告警。
**一个会被忽略的告警，比没有告警更糟** —— 它把真正的越界也一起埋了。

## 二、切句：`[1]` 到底归上句还是下句

这是本单元唯一必须手写循环的地方，用正则 `re.split` 一定错。

```
"甲句。[1]乙句。"  →  ["甲句。[1]", "乙句。"]   ✅
"甲句。" / "[1]乙句。"                            ❌ 硬切的结果
```

错在哪：`[1]` 跑到下一句开头，于是上一句「没引用」被计进 `no_citation`，
下一句 `strip_refs` 之后只剩 `乙句。`，编号却挂在它头上。覆盖率从 1.0 掉到 0.5 甚至 0.0，
伪造检测拿错句去比来源，结果全是噪音。

实现是**逐字符扫**：遇到 `。！？；\n` 之后，`while CITE_RE.match(text, i)` 把紧跟的编号吸进当前缓冲。
不能用 `re.split` 的原因很直接 —— 分隔符之后还有属于分隔符之前的内容，`split` 表达不了这件事。

## 三、覆盖率的分母

分母 = **有内容的句子**，不是「所有句子」。

`has_content()` 用 `bool(re.search(r"[0-9A-Za-z\u4e00-\u9fff]", text))` 卡一道。
没有这道卡，答案末尾一个换行、一个句号就变成一条「没引用」的句子，覆盖率被凭空稀释。
实测：`validate("。[1]", S)["coverage"] == 0.0` —— 整段只有一个标点，分母为 0，返回 0 而不是除零崩掉。

## 四、伪造引用：编号对、内容错

这是本单元真正想讲的东西。

- 越界（`[9]` 只有 4 条来源）是最笨的错法，一个 `if n > len(sources)` 就抓完了。
- 真正的主流错法是模型引用一条**真实存在**的来源，然后写一句那条来源从来没说过的话。

实测支撑度（6 字滑窗有多少比例能在来源里找到）：

| 句子 | 支撑度 |
| --- | --- |
| 逐字引用「跨年未休完的年假最多结转 5 天。[2]」 | 0.917 |
| 同义改写「年假可以一直留着以后再用」 | 0.000 |
| 编造「年假可以无限期结转，离职时按三倍工资补偿。[2]」 | 0.000 |
| 无关句「今天天气不错适合出门散步」 | 0.000 |

注意第一行：**逐字引用也拿不到 1.0**。来源里这句结尾是「，」，答案里被改成「。」，
最后一个 6 字窗口落在来源之外，扣掉一格。所以阈值不能设 0.95，`FABRICATED_BELOW = 0.5` 才是安全余量。

反过来说，这个方法对**同义改写**完全无能为力 —— 意思一样、字不一样，支撑度是 0，直接判伪造。
这是 6 字滑窗的固有局限，不是实现 bug。真要做同义改写下的引用校验，得上 embedding 相似度（Unit 15/20 的事），
代价是阈值更难解释、误报更难排查。本章选了简单可解释的那条，并且把局限写在测试里。

## 五、定位：为什么不用 `find()`

`locate()` 用的是 `difflib.SequenceMatcher(...).find_longest_match()`。

实测：完整句对来源 1 定位到 `[0, 28)`；把句尾「，由直属主管审批。」砍掉只留半句，定位到 `[0, 19)`。
如果换成 `source_text.find(snippet)`，第二种情况直接返回 `-1` —— 因为它要求**整串精确出现**。

而答案几乎从来不会和来源一字不差：句尾多一个标点、引用半句、把「3 个工作日」写成「三个工作日」。
最长公共块的价值在于：即使匹配不到全长，它也能告诉你「最接近的是从第 0 字起的 19 个字」，
比一个 None 有用得多。`min_len = NGRAM = 6` 是最后一道闸，防止 2 个字的巧合被当成命中。

## 六、渲染：顺序就是安全性

```python
safe = html.escape(answer, quote=True)   # 先
body = CITE_RE.sub(repl, safe)           # 后
```

反过来的话，答案里的 `<img src=x onerror=alert(1)>` 会先被浏览器解析成标签，再被 `sub` 插进角标 —— 执行了。

转义之后答案里不可能再有 `<`，所以后面插入的 `<sup class="cite"><a href="#src-1">` 一定是「我们自己的」。
`href` 和 `data-i` 里只放整数编号（`int(m.group(1))`），不可能混进引号或 `javascript:` 前缀。

自检里专门测了这些：`<script>` 被转成 `&lt;script&gt;`、`<img` 不出现、
引号被转成 `&quot;` 拆不出新属性（`'[1]" onmouseover="alert(1)'`）、
以及**转义后的 `[1]` 仍然能正确变成 sup**（替换发生在转义之后，所以 `&lt;b&gt;[1]` 里的 `[1]` 照常工作）。

越界引用不能静默丢掉：渲染成 `<span class="cite-bad">[9]</span>`，页面上带红色下划线和 tooltip。
用户看得见「这里引了个不存在的东西」，比它凭空消失强。

## 完成标准对照

| 标准 | 达成情况 |
| --- | --- |
| 能拆出逐句 + 编号 + 支撑度 | `validate()` 返回 `sentences[]`，页面②逐句表直接展示 |
| 能指认越界 / 未引用 / 伪造 | `out_of_range` / `no_citation` / `fabricated` 三个字段，6 个案例各打一个 |
| 能说清先转义后替换 | 见「六、渲染」，自检有 6 条 XSS 相关断言 |
| 能定位回原文 | `/locate` 返回 `start/end/matched`，页面④展示高亮片段 |
| 离线可自检 | 64 条断言，0 失败，无需 key |

## 一句话总结

**引用系统的产出不是角标，是一张「这句话凭什么」的证据表**；角标只是这张表的入口。

## 面试追问

**Q：为什么不直接用 LLM 判断「答案是否被来源支持」，要做滑窗？**
A：成本和延迟都不允许每句一次模型调用；更关键的是不可解释 —— 模型说「支持」，你没法复核。
滑窗支撑度虽然粗，但它是确定的、可复现的、能给具体数字的，而且失败时能指到具体哪 6 个字没匹配上。
工程上先用廉价确定性方法兜住 90% 的明显伪造，剩下的模糊地带再交给模型或人。

**Q：`ok=False` 和覆盖率低，哪个更严重？**
A：`ok=False` 是硬伤（越界或伪造），意味着这句话在有据可查的意义上是假的，必须拦。
覆盖率低是软问题，可能只是模型偷懒没标编号，内容本身没错。所以这两件事必须是两个指标，
UI 上也要分开显示 —— 合并成一个绿灯，等于把「内容编造」和「格式偷懒」画等号。

**Q：这套校验能上生产吗？**
A：作为**离线评估**可以用，作为**在线拦截**要谨慎。它在同义改写上误报率高（实测 0.000），
真的按 0.5 阈值拦，会把大量正确但改写过措辞的答案拦下来。生产上的做法是：
在线只拦越界（零误报），把支撑度写进日志供抽样审计，定期人工看低分样本再调整阈值。

**Q：如果答案里有 200 个引用，这个渲染会不会有性能问题？**
A：`CITE_RE.sub` 是单次线性扫描，`html.escape` 也是，200 个引用在微秒级。
真正的性能风险在 `locate()` 的 `difflib`：它是 O(n·m)，来源长、句子多的时候会明显变慢。
所以本单元只在用户点「定位」时单条调用，不在生成时批量跑。
