# Unit 21 · Citation 引用系统

> 让答案里的 `[1][2]` 真的能回到原文件、原页码、原句。引用不是排版装饰，而是可核查性。

**完成标准**：能把一段答案拆成「逐句 + 编号 + 支撑度」三列，当场指认出越界、未引用、伪造三类问题，
并说清 `render()` 里为什么必须先转义、后替换 —— 顺序反了就是一个 XSS。

## 快速开始

```bash
cd ~/ai-journey/unit21-citation
uv sync
uv run uvicorn main:app --reload --port 8021
```

打开 http://127.0.0.1:8021/ 。离线，不需要 key。四个面板：写答案 → 看体检报告 → 看渲染结果 → 点「定位」回到来源原文。

## 实测

四个体检项跑 6 个案例，数字全部来自 `python main.py` 与接口实跑：

| 案例 | 想演示什么 | 覆盖率 | 引用 | 越界 | 伪造 | ok |
| --- | --- | --- | --- | --- | --- | --- |
| `good` | 三句都带引用 | 1.00 | [1,2,3] | — | 0 | ✅ |
| `partial` | 第二句没标引用 | 0.50 | [1] | — | 0 | ✅ |
| `out_of_range` | `[9]` 但只有 4 条来源 | 1.00 | [1,9] | [9] | 0 | ❌ |
| `fabricated` | 编号对、内容来源里没有 | 1.00 | [2] | — | 1 | ❌ |
| `year` | `[2026]` 不是引用 | 1.00 | [1] | — | 0 | ✅ |
| `xss` | 答案里带 `<script>` | 0.50 | [1] | — | 1 | ❌ |

支撑度（6 字滑窗命中比例）的实际分布：

| 句子 | 支撑度 | 判定 |
| --- | --- | --- |
| 逐字引用「跨年未休完的年假最多结转 5 天。[2]」 | 0.917 | 通过 |
| 同义改写「年假可以一直留着以后再用」 | 0.000 | 判伪造 |
| 无关句「今天天气不错适合出门散步」 | 0.000 | 判伪造 |
| 案例 `fabricated`「年假可以无限期结转…[2]」 | 0.000 | 判伪造 |

定位实测：完整句 → 区间 `[0, 28)`；只引半句（少 9 个字）→ `[0, 19)`。用的是最长公共块，不是 `find()`。

## 常见坑

1. **`[1]` 被切到下一句**。中文把引用写在句号**后面**（`……审批。[1]`），按标点硬切的话 `[1]` 成了下一句开头，
   上一句「没引用」、下一句「只有一个编号」。覆盖率直接腰斩，伪造检测跟着全失效。
   正确做法是切到句号后立刻 `while CITE_RE.match(text, i)` 往后吸。
2. **覆盖率分母灌水**。空句、纯标点的「。」不配有分母。`has_content()` 用 `[0-9A-Za-z\u4e00-\u9fff]` 卡一道。
3. **`[2026]` 被当成引用**。正则必须限位 `\[(\d{1,2})\]`。放宽到 `\d+` 的话，中文文档里的年份全是误报，
   然后所有人开始忽略告警 —— 告警一旦被忽略就等于没有。
4. **先替换后转义 = XSS**。`html.escape` 必须在 `CITE_RE.sub` **之前**。转义后答案里不可能再有 `<`，
   之后插进去的标签就一定是自己的。反过来做，答案里一个 `<img src=x onerror=alert(1)>` 会被浏览器直接执行。
   所以 `href="#src-{n}"` 里的 `n` 只接受整数，绝不拼接任何来自用户串的属性。
5. **只查越界 = 漏掉最主流的编法**。模型最常见的伪造是「编号对、内容错」，不是瞎编编号。
   越界检查对它一无所知，必须再算一次支撑度。
6. **`ok=True` 不等于答案好**。`partial` 案例 50% 的句子没引用，`ok` 仍是 `True` ——
   `ok` 只回答「有没有硬伤」（越界 / 伪造），覆盖率是软指标，得单独看。把两者混成一个绿灯，就是在自欺。
