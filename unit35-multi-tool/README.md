# Unit 35 · 多工具路由

> 工具从 2 个加到 5 个，执行逻辑一行没改 —— 掉的是路由准确率。

**完成标准**：能跑出「描述完整 / 含糊 / 删掉」三档准确率，并说清为什么删掉 `description` 之后路由会垮。

## 快速开始

```bash
cd ~/ai-journey/unit35-multi-tool
uv sync
uv run uvicorn main:app --reload --port 8035
```

打开 <http://127.0.0.1:8035/>：输入问题，左边看「为什么选它」（命中了哪些字片段、IDF 分数多少），
右边是四个配置的 10 题准确率。点「没有对应工具」看误选长什么样。

## 自检

```bash
uv run python main.py
```

51 项，全离线：5 个工具各自被路由到、四档准确率、误选被记录、并行 2/3 个调用、
`call_id` 对应、参数抽取、一个工具坏了不影响另一个、HTTP 层。

| 文件 | 说明 |
| --- | --- |

## 实测

同一批 10 道固定题，只改工具描述，准确率（`accuracy()` 的真实输出）：

| 配置 | 命中 | 准确率 | 掉在哪 |
| --- | ---: | ---: | --- |
| 五工具 · 描述完整 | 10/10 | **1.00** | — |
| 五工具 · 描述含糊（「处理换算相关的请求」这种） | 9/10 | 0.90 | `SO-000456 现在什么状态` → 分数 0，选不出来 |
| 五工具 · 删掉 description | 6/10 | 0.60 | 计算类 2 题、订单类 2 题全丢 |
| 两工具（只有天气 + 计算） | 4/10 | 0.40 | 缺 3 类能力，4 题被硬塞给天气 |

并行调用的实测（`ask()` 返回）：

| 问题 | 调用数 | 结果 |
| --- | ---: | --- |
| 上海和北京今天多少度 | 2 | `get_weather(上海)` + `get_weather(北京)`，两个 id 分别回填 |
| 上海、北京、广州今天下雨吗 | 3 | 三个调用，三条 tool 消息 |
| 100 美元能换多少人民币 | 1 | `convert_currency(100, 美元, 人民币)` → 710.0 |
| 5 公里是多少米 | 1 | `convert_unit(5, 公里, 米)` → 5000.0 |

单次工具耗时 **0.0~0.1 ms**（纯本地计算）—— 所以本单元的并行不是为性能，是为**形状正确**：一个 assistant 消息对应 N 条 tool 消息，漏一条就是 400。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 五个工具名与当前模型 |
| GET | `/tools` | 完整工具声明（页面直接渲染） |
| POST | `/route` | 只要路由结论：选中谁、得分、命中了哪些片段、其他候选 |
| POST | `/ask` | 路由 → 并行执行 → 按 id 回填 → 回答 |
| GET | `/bench` | 四个配置 × 10 题的准确率与逐题明细 |

## 常见坑

**1. 工具名是英文、问题是中文，光靠名字一点交集都没有。** 本单元路由器把 `name.replace("_"," ")` 一起切进词表，但实测「删掉 description」后中文问题在名字上命中数为 0 —— 准确率从 1.00 掉到 0.60。名字是给人看的，`description` 才是给路由用的。

**2. 没有对应工具时，路由器不会说「我不知道」。** 实测「深圳到北京的机票多少钱」被塞给 `get_weather`（分数 12.66，相当自信）—— 因为「深圳」「北京」是天气工具枚举里的城市名。这在链路上不会报错，只会产出一个用天气回答机票问题的答案。**能返回 `None` 的路由器比总能选一个的更安全。**

**3. 两个工具描述写得像，就会互相抢。** 「换算」这个词同时出现在货币和单位工具的
描述里时，两个分数会非常接近（实测 `convert_unit` 20.338 vs `convert_currency` 15.539，只差 4.8）。
描述里必须写出**区分点**：「货币/汇率」vs「长度重量温度」。

**4. 并行调用要按 `tool_calls` 的顺序回填，不是按结果到达顺序。** 串行执行时两者一致，
一旦真并行（`asyncio.gather`）完成顺序是随机的 —— 回填顺序错了，日志里 id 和参数就对不上，
排查时你会以为模型传错了参数。

**5. 一个工具抛异常不能带走整批。** `execute_calls()` 里每个调用单独 `try`，失败的那个返回 `{"error": ...}` 的 tool 消息，其余照常返回。自检里「杭州 + 北京」两个调用：第一个失败、第二个成功，两个都要回填。

**6. 工具数量增加 ≠ 能力按比例增加。** 两个工具时准确率 4/10，五个工具 10/10 —— 但这是同一批题（其中 6 题 2 个工具根本答不了）。换成「5 个工具 + 20 个候选」时，准确率会掉回去，而题集没变。所以准确率必须和**工具数量、题集**一起报，单独说「准确率 95%」没有意义。
