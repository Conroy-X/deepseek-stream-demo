## 实测（本单元的成绩单）

3 份文档（员工手册 / 退款政策 / 安全规范）→ 6 个 chunk（90 字、overlap 20），10 道题：

| 指标 | 值 |
| --- | --- |
| 答案准确率（含关键片段） | **1.00** |
| 来源命中率（引用指向正确文件） | **1.00** |
| 引用覆盖率（每题都带 [n]） | **1.00** |
| 无关问题拒答 | **正确** |

拒答阈值是**量出来的**，不是拍的：

| 问题类型 | top1 向量分数 |
| --- | --- |
| 相关（年假/退款/密码…） | 0.177 – 0.260 |
| 无关（年会抽奖/天气/股票） | 0.078 – 0.099 |

分界取 **0.12**。换 embedding 模型必须重测 —— 这个数不是通用常数。

## 三个必须做对的点

**1. 切块太大会毁掉一切**

第一版用 220 字切块，3 份文档各切成 1 块。结果：所有问题的 top1 分数都被
"整篇文档的平均相似度"稀释到 0.1 附近，相关的和不相关的混在一起，拒答根本做不了。

改成 90 字后，相关与无关的分数才分得开（0.177+ vs 0.1-）。**切块粒度直接决定阈值可不可用。**

**2. 引用必须是"数据"，不是"文本里的装饰"**

`answer()` 返回的 `citations` 是结构化数组（id/chunk_id/source/page/snippet），
正文里的 `[1]` 只是它的渲染。两者由同一个循环生成，所以不可能对不上。

如果让模型自由写 `[1]`，再回头去"猜"它指的是哪条 —— 那是伪造引用的开始。

**3. 拒答要在"检索层"判断**

```python
if not hits or hits[0].score < MIN_SCORE:
    return {"answer": REFUSAL, "refused": True, "citations": []}
```

不是让模型"自己决定要不要编"。模型没有"不知道"这个状态，它只有"继续生成"。

## 限制（写在交付里，不藏着）

- **没有接真实 LLM**：离线用"挑最像的一句"当生成。接模型只需替换 `_best_sentence` 那段，
  prompt 与引用规则不变。
- **评测集只有 10 题**，且是自造语料。真实项目要 50 题起，覆盖同义改写与多跳问题。
- **单租户**：`TENANT = "demo"`。多租户隔离在 Unit 25 已验证，这里没接鉴权（Unit 29 的事）。
- **语义能力受限于本地哈希向量**：同义改写会掉分（Unit 25 实测 0.667）。
