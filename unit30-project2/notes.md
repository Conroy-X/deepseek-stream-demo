## 一、组装时暴露的第一个问题：切块太大

第一版 `size=220`，三份演示文档各切成 **1 块**。后果不是"检索不到"，而是更隐蔽的：

| 问题 | top1 分数 |
| --- | --- |
| 年假要提前几天申请（相关） | 0.130 |
| 公司年会抽奖有什么奖品（无关） | 0.095 |
| 今天天气怎么样（无关） | 0.104 |

相关的和无关的差不到 0.04 —— 任何阈值都会同时误杀或漏放。

改成 `size=90, overlap=20` 后：

| 问题 | top1 分数 |
| --- | --- |
| 相关（年假/退款/密码/病假） | 0.177 – 0.260 |
| 无关（抽奖/天气/股票） | 0.078 – 0.099 |

差距拉开到 0.08 以上，阈值才站得住。

**教训：chunk 太大 → 向量被平均 → 阈值失效 → 拒答做不了。**
这三个问题是连锁的，而根因在 Unit 18 的一个参数上。

## 二、拒答必须在检索层做

```python
if not hits or hits[0].score < MIN_SCORE:      # MIN_SCORE = 0.12
    return {"answer": REFUSAL, "refused": True, "citations": []}
```

曾经想过"让模型自己判断知不知道"，很快否掉了：模型的输出空间里没有"不知道"，
它只有"下一个 token"。指望它自觉拒答，等于把幻觉概率交给运气。

现在的做法是：**检索层给出可量化的把握度（top1 分数），低于阈值就直接拦死**，
模型根本没机会开口。

## 三、引用是数据结构，不是字符串

```python
citations.append({
    "id": i, "chunk_id": c.chunk_id, "source": ..., "page": ..., "snippet": sent,
})
body = "根据资料：" + " ".join(f"[{i}] {sent}" for ...)
```

正文里的 `[n]` 和 `citations[n-1]` 由**同一个循环**生成，所以天然对齐。
自检里钉了一条：`citations 与编号一一对应`，以及 `citation 的 snippet 必须出现在答案里`。

反例（很多 demo 这么写）：让模型自由输出 `[1][2]`，再回头正则匹配去猜它引的是谁。
一旦模型编一个 `[5]` 而只有 3 条来源，前端就只能装作没看见。

## 五、诚实的限制

- **生成是离线模拟**：`_best_sentence` 挑最像的一句，不是真模型生成。
  接真模型只改这一个函数，prompt 与引用契约不动。
- **10 题、自造语料**：recall 1.0 只能说明"在这个小语料上没掉链子"，
  不能写成"准确率 100%"。
- **单租户**：隔离能力在 Unit 25 验证过，这里没接鉴权（Unit 29 的活）。
- **本地哈希向量**：同义改写会掉分（Unit 25 实测 recall 0.667），
  所以这套东西的真实上限是"字面能找到的问题"。

项目 2 的难点从来不是"再加一个功能"，而是**把前面十个单元的参数调到互相不打架**：

## 面试追问

1. **「你这个项目的准确率怎么算的？」**
   → 10 题固定评测集，每题标注"答案必须包含的原文片段"和"应引用的来源文件"，
   逐题判 `must in answer` 与 `source in citations`。指标定义写在 README，
   `uv run python main.py` 可复现。不会说"感觉挺准"。

2. **「无答案的问题怎么处理？」**
   → 检索层算 top1 分数，低于实测阈值（0.12）直接拒答，且返回空 citations。
   不让模型自己判断 —— 模型没有"不知道"这个状态。

3. **「为什么切 90 字？」**
   → 因为答案本身长 20–60 字，块要比答案大但不该装下多个主题。
   实测 220 字时相关/无关分数只差 0.04，阈值失效；90 字时差 0.08 以上。
   这个数是量出来的，不是查来的。

4. **「如果换成真 LLM，架构要改吗？」**
   → 只改生成那一段：把 `_best_sentence` 换成 API 调用，prompt 里带上编号上下文，
   并要求"只允许引用给定编号"。检索、重排、引用校验、拒答阈值全都不动。
