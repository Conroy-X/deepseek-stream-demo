# Unit 36 · Agent 错误处理

> 工具一定会坏。好的 Agent 不是不会坏，是坏了之后还能说清「哪一步坏了」。

**完成标准**：四种故障（异常 / 超时 / 死循环 / 重复调用）各有一条断言，并且正常路径的行为一个字都没变。

## 快速开始

```bash
cd ~/ai-journey/unit36-agent-errors
uv sync
uv run uvicorn main:app --reload --port 8036
```

打开 <http://127.0.0.1:8036/>：上面一排故障注入按钮，点「超时 3 秒」看它 500ms 就放弃，
点「强制死循环」看第 3 步熔断，点「重放同一调用」看副作用为什么只发生一次。

## 自检

```bash
uv run python main.py
```

49 项，全离线：异常不冒泡、超时 1 秒内返回、并发里一个超时不影响其他、
熔断在第 N 次触发且执行前拦截、幂等只执行一次、正常路径未受影响、HTTP 层。

## 实测

四种故障的真实数据（`scenario()` 的输出）：

| 场景 | 停止原因 | 步数 | 墙钟 | 工具真正执行 | trace 里的工具状态 |
| --- | --- | ---: | ---: | ---: | --- |
| 正常 | `answer` | 2 | 10.4 ms | 1 | `ok`（10.3 ms） |
| 抛异常 | `answer` | 2 | 0.1 ms | 1 | `exception` |
| 超时（预算 0.5s，工具睡 3s） | `answer` | 2 | **500.8 ms** | 1 | `timeout`（500.7 ms） |
| 死循环 | `loop_detected` | 3 | 20.7 ms | **2** | `ok` ×2，然后 `breaker` |

两个数字值得盯：

- 超时场景墙钟 **500.8ms**，工具本身要睡 3000ms —— 差的就是 `wait_for` 省下的 2.5 秒。
- 死循环场景走了 3 步，但工具只执行了 **2 次**：熔断检查在执行**之前**，第 3 次调用根本没发出去。

幂等实测：同一个 `tool_call_id` 调两次，`effect_no` 都是 1（副作用只有一次）；
换一个 key 才变成 2。`replays` 计数为 1。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 工具与默认超时预算 |
| GET | `/tools` | 工具声明 |
| POST | `/run` | 正常跑一次（无故障） |
| POST | `/fault` | `{kind: none\|raise\|timeout\|loop\|replay, budget}` 注入故障 |

`/fault` 返回 trace、`wall_ms`、`tool_calls_executed`、`breaker_events` ——
这四个字段就是「故障时到底发生了什么」的完整证据。

## 常见坑

**1. `asyncio.wait_for` 取消的是那个协程，不是整个 `gather`。** 早期我用的是「整批超时」，
结果一个坏工具把同批的好工具一起废掉。自检里三个并发调用（都超时）实测 1.5 秒内全部返回，
而不是串行 3+3+3 秒。

**2. 熔断检查必须在执行之前。** 第 3 次重复调用如果先执行再判断，退款就已经退第二次了。
实测 `tool_calls_executed == 2`（不是 3）就是这条的直接证据。

**3. 熔断了，但 messages 还得合法。** 你拦下了工具，但 assistant 那条消息里已经写了 `tool_calls`，
不补 tool 消息的话数组就是「有请求没应答」的非法态。所以熔断时要补一条
`{"kind": "blocked"}` 的 tool 消息 —— 这条规则从 Unit 33 一直用到这儿。

**4. 幂等键要用 `tool_call_id`，不是「参数相同」。** 用户可能真的想买两次同样的东西，
参数一样但调用不同。而没有 id 的工具（定时任务）只能用业务键（订单号），
此时「两次相同请求」就无法区分 —— 这是设计取舍，要在文档里写清楚。

**5. 超时预算不是越大越安全。** 预算 3 秒 × 3 个工具 × 5 步 = 45 秒，用户早关了页面。本单元用 0.5~1 秒，因为工具是本地计算；真实 HTTP 工具通常 5~10 秒。预算要按**整条链路**算，不是按单个工具。

**6. 「重试」和「幂等」是两件事。** 重试解决的是「这次没拿到结果」，幂等解决的是
「上次其实已经成功了，只是我没看到」。只做重试不做幂等，就是经典的重复扣款事故。
