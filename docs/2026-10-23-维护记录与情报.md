## 四、顺手发现的问题（都没改，留给你决定）

### 1. 成本估算漏掉了「缓存命中价」，而且是 50 倍的差距 —— 建议优先改

`unit03/llm.py`、`unit04/llm.py`、`unit05/llm.py` 里都是：

```python
PRICE_INPUT_PER_M = 1.0
PRICE_OUTPUT_PER_M = 4.0
```

按官方价目表，1.0 / 4.0 对应的是**空闲时段 + 输入未命中缓存**。
但输入还有一档 **缓存命中价 0.02 元/M**（空闲），是未命中的 **1/50**。

这为什么重要：你的 CLI Chat 每轮都把 `System + 全部历史` 重发一遍，**前缀是完全重复的**，
正好是自动上下文缓存的主场。也就是说 `/tokens` 打出来的「约 ¥0.0xxx」在多轮对话里会**明显高估**。

响应里本来就有这两个字段（`unit03/debug_response.py` 第 176 行已经在读了）：

```python
u = resp.usage
hit   = getattr(u, "prompt_cache_hit_tokens", 0) or 0
miss  = getattr(u, "prompt_cache_miss_tokens", 0) or 0
cost  = hit / 1e6 * 0.02 + miss / 1e6 * 1.0 + completion / 1e6 * 4.0
```

`Usage.add()` 加两个字段、`cost_cny` 换上面这行，就是这个单元的「选做」。
（顺带：高峰时段全部 ×2，你代码注释里已经写对了。）

### 2. `unit10` 的 64K 上下文假设已经偏保守

`unit10-context/context.py:221` 是 `total: int = 64_000`。现在 `deepseek-flash` 的**上下文是 1M**。
作为教学默认值没问题（64K 让「裁剪」这件事更直观），但笔记里最好注一句
「真实窗口 1M，这里用 64K 是为了让收益率看得见」—— 否则面试被问到会露馅。

### 3. 笔记位置跟计划文档不一致

`docs/学习单元计划.md` §9 让你把笔记放 `docs/unitNN.md`，实际你（和之前的会话）都写在
`unitNN/notes.md` 里。两种都行，但建议把 §9 改成 `unitNN/notes.md`，免得以后自己对着文档找文件。

### 4. `unit05` 没有跟其它单元统一的 `selfcheck.py`

其它单元都是「一条命令 + N 项断言」，unit05 只有 `models.py` 的校验演示（打印 ✅/🚫 但没有计数）。

`selfcheck.py` 即可（10 分钟活）。
