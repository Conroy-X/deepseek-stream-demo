**网络限制与对策（这台机器特有，重要）**

| 现象 | 根因 | 对策 |
| --- | --- | --- |
| `registry-1.docker.io` / `auth.docker.io` 全部超时 | **DNS 污染**（被解析到 108.160.162.98 等无关 IP），不是墙 | 已配镜像加速器 `docker.m.daocloud.io` + `docker.1ms.run`，实测 10 秒拉下 alpine |
| `download.docker.com` 间歇失败 | IPv4 可达但 IPv6 无路由（本机 0 个全局 IPv6 地址） | Docker 源改用 **USTC 镜像** `mirrors.ustc.edu.cn/docker-ce` |
| `raw.githubusercontent.com` 不通 | 网络限制 | 装脚本类资源改走 gitee / USTC 镜像 |

> **写脚本的坑**：`curl ... | echo "$PW" | sudo -S tee` 这种串联会让 sudo 从 stdin 抢走 curl 的数据，
> 表现为「GPG key 下载失败」但实际网络正常。正确做法是先 `echo "$PW" | sudo -S -v` 建立凭据缓存，
> 之后直接用 `sudo`，不要在同一条管道里既传密码又传数据。
