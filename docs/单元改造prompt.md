## 环境事实（必读，别重新探索）

- 代码在 WSL：`ssh wsl-debian`，仓库 `~/ai-journey/`，每个单元一个目录，一个单元一个端口（Unit 11=8011 … 递增）。
- WSL 网络：**全局代理已配好**（`/etc/environment`，非登录 shell 也生效），装包直接用官方源即可。若 `uv.lock` 里残留旧镜像 URL 导致 `Failed to fetch ... 403`，跑 `uv lock --refresh`。

  骨架里若写 `postgres:postgres@127.0.0.1:5432` 必然失败 —— 改连接串，别改 `pg_hba.conf`。
- sudo 密码：`Whatever1024`（需要改 `/etc` 类操作时用 `echo Whatever1024 | sudo -S -p "" ...`）。
- 素材对照：已完成的 `unit15-embedding`（自检风格）、`unit16-pgvector`（本轮改造范本）可直接参考。

## 改造标准（Definition of Done，逐条都要满足）

1. **环境自检通过**：`check_env.py`（若有）或等价脚本全绿；没有就补一个最小版（连依赖、连库、验关键能力）。
2. **单元自检全过**：`uv run python main.py` 输出「N 项通过 / 0 失败」，**N ≥ 12**，覆盖：依赖可用、核心路径正确、边界情况、错误处理、幂等性。自检不依赖启动服务。
3. **端到端冒烟**：起服务 → 用 `curl` 打每个路由 → 关服务。首页/静态资源返回 200 且标题正确。
4. **骨架里所有 TODO 都实现**，且**每个实现点旁边留"为什么"的注释**（踩坑、错误写法对比、边界条件），不能只留代码。教学价值在注释里，不在代码里。
5. **实测数据（有对比/性能类知识点时必做）**：写 `bench.py` 或等价脚本，产出可复现的数字表，写进 notes。没数据支撑的结论一律不写。
6. **性能类实验必须显式验证执行计划**：`EXPLAIN` 确认真的走了预期路径；调参导致的退化（例如计划回退成全表扫）要写进笔记，这是最值钱的发现。
7. **notes.md 补齐**：
   - 该单元的「完成标准」问题，写成**参考答案**（明确标注"建议自己先写一遍再对照"）
   - 实测数据表 + 环境信息（版本/数据量/参数/取中位数次数）
   - 「踩过的坑」：真实报错信息 + 根因 + 修法，不写正确的废话
   - 自检清单勾选状态
8. **README 更新为现实**：状态、快速开始命令、文件清单、TODO 答案要点、实测结论、与前后单元的交接事项（例如下一单元要提前加的字段）。
9. **收尾干净**：压测/演示数据删掉并 `VACUUM`（数据库类单元），临时脚本清掉或归类，不能让垃圾数据污染后续单元。
10. **不提交、不推送 git**：`git status` 结果汇报给我，由我决定何时提交。

## 执行流程

**阶段 0 · 侦察（不改任何东西）**
读该单元的 `README.md`、`notes.md`、`main.py`、`pyproject.toml`、`check_env.py`，以及 `docs/学习单元计划.md` 里对应那条。
输出：现状（骨架到什么程度）、缺口清单、TODO 列表、该单元真正要考的知识点。

**阶段 1 · 环境**
先跑骨架自检。报错就先修环境（连接串、依赖、端口、路径），**环境不通不往下写代码**。
把环境问题本身记进 notes 的坑列表。

**阶段 2 · 实现**
逐个 TODO 实现，注释写"为什么"。保持原有函数签名和路由，不擅自改 API 形状。
实现顺序：数据/核心逻辑 → 路由 → 边界与幂等 → 统计/观测。

**阶段 3 · 自检**
把 `main.py` 的 `__main__` 做成完整自检（≥12 项），风格照 unit15/unit16：
`1 项目名 ✓ 说明` / `✗ 错误摘要`，末尾 `通过 N / 失败 0`，失败时退出码非 0。
必须包含「故意错的情况」：重复插入、空表、维度不匹配、跨路径结果一致性等。

**阶段 4 · 实测**
需要量化的知识点 → 写 `bench.py`；需要参数取舍 → 写 `sweep.py`。
**先验证造出来的数据符合预期分布**（这一点 Unit 16 翻过两次车），再谈指标；否则数字全是假的。

**阶段 5 · 冒烟**
起服务打真实请求（写成 `smoke.sh` 便于复跑），确认：静态页 200、每个路由正常返回、错误输入返回合理状态码。

**阶段 6 · 文档**
更新 `notes.md` 与 `README.md`（按第 7、8 条），数据必须是阶段 4 跑出来的真值。

**阶段 7 · 收尾**
清测试数据、VACUUM、检查 `git status`，然后汇报。

## 工程约定

- 全部中文注释与文档；代码用 `from __future__ import annotations`、类型标注、无第三方格式化依赖。
- 依赖用 `uv` 管理（`uv sync` / `uv run`），不往全局装包；压测专用依赖（如 numpy）在 pyproject 里注明"只给 bench 用"。
- 自检/冒烟脚本必须能重复跑，结果幂等（重复插入走 upsert 或跳过，不留重复行）。
- 数值必须有来源：写进笔记的每个数字，都要能从某个脚本一条命令跑出来。
- 结论优先于描述：笔记里少写"是什么"，多写"所以怎么选 / 什么时候别这么干"。

## 禁止事项

- 不伪造、不估算、不"合理推测"实测数据；跑不出来就写"没测"。
- 不把学习和验收颠倒：TODO 是考点，实现要有注释解释，不能只交代码。
- 不顺手重构无关单元、不改其他单元的文件。
- 不擅自 `git commit` / `git push`。
- 不为了凑指标写无意义的检查项（例如恒真的断言）。
