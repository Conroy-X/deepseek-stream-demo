# 安全与隐私规则（必读）

> 本仓库是**公开**仓库。以下规则适用于本仓库产出的**所有代码、文档、笔记、示例数据**。

---

## 铁律

### 1. 绝不出现真实个人信息

包括但不限于：

| 类型 | ❌ 错误示例 | ✅ 正确写法 |
| --- | --- | --- |
| 真实姓名 | `你的真名` | `张三` / `用户A` / `示例用户` |
| 手机号 | `13812345678` | `138****0000（示例）` |
| 邮箱 | `zhangsan@qq.com` | `zhangsan@example.com` | <!-- pii-check: allow 反例说明 -->
| 身份证 | 真实 18 位 | 不要出现，连脱敏的都不要 |
| 学校 | `你的毕业院校` | `某某大学` |
| 公司 | `你就职的公司名` | `某科技公司`、`某互联网公司` |
| 地址 | `省市区街道门牌` | `某市某区` |
| 工号/内部代号 | `工号`、`内部项目代号` | 不要出现 |

**示例数据一律用虚构值**，且明确标注「示例」。`example.com` 是 RFC 2606 保留域名，可安全使用。

### 2. 绝不提交密钥

- API Key 只放 `.env`（已在 `.gitignore`）
- 代码里用 `os.getenv("XXX_API_KEY")`，绝不硬编码
- 提交前跑一次扫描（见下方脚本）

### 3. 简历类数据要脱敏

本路线里有多个"简历抽取"练习。**用自己真实简历练手是好事，但仓库里只能放脱敏版本**：

- 姓名 → 张三
- 学校 → 某某大学
- 公司 → 某科技公司
- 电话 → 138\*\*\*\*0000
- 邮箱 → zhangsan@example.com

真实数据放本地、不提交。

## 提交前自检

```bash
# 扫描整个工作区
python3 ~/ai-journey/00-setup/check-pii.py

# 扫描待提交的改动
git diff --cached | grep -inE '1[3-9][0-9]{9}|@(qq|163|gmail)\.com'
```

任一命中就**不要提交**。

---

## 万一已经提交了

1. **先停下**，不要再往上叠加新提交
2. 用 `git filter-repo --replace-text` 改写历史
3. `git push --force`
4. **注意**：GitHub 会保留孤儿提交对象，通过 `api.github.com/repos/OWNER/REPO/commits/<旧SHA>` 仍可能访问到 diff
   - 彻底清除需要**删除仓库重建**或联系 GitHub Support

> 2026-10-18 这次事故就是这么发生的：示例简历里放了真实姓名/学校/雇主，
> 强推后 `main` 干净了，但孤儿提交的 diff 仍可访问，最终只能删库重建。
> 教训：**连"错误示例"里都不要写真实信息**，否则它本身就是泄露。

---

## 为什么这条规则重要

- 公开仓库 = 全网可搜、可被爬虫抓取、可被长期存档（GitHub Archive、各种镜像站）
- 简历信息拼起来足以做社工攻击：姓名 + 学校 + 公司 + 工作时间
- 面试官搜你的 GitHub 时，看到的是"这批代码的规范性"——包含真实 PII 本身就是负面信号
