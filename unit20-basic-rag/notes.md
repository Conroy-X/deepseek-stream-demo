## 一、离线答案为什么必须逐字摘原文

第一版我写的是「抽关键词重新组句」，看着更像人话，但两件事立刻崩了：

1. 没法断言。除了「答案看起来对」，你没有任何机械可验的东西。
2. Unit 21 做不了。Citation 校验的核心是「答案里这句话，在来源第几段能原样找到」——
   改写过半句就再也对不上。

改成逐字摘原句之后，自检变成这样：

```python
check("答案包含检索到的原句（逐字）",
      all(p["sentence"] in hits[p["idx"] - 1].text for p in picked))
check("去掉标号后每句都能在 hits 里找到原文", ...)
```

实测答案：

```
年假要提前几天申请 → 年假需提前 3 个工作日在系统提交申请，由直属主管审批。[1]
退款多久到账       → 退款金额原路退回，到账时间以支付渠道为准，通常 3–5 个工作日。[1]
```

## 二、跨段拼句子是第一个真坑

一开始每个命中段各挑一句，用分数排序取前两句。跑「一线城市住宿标准」得到：

```
住宿标准：一线城市每晚不超过 600 元，其他城市不超过 450 元。[1]
超时未到账请提供订单号与支付流水号。[2]
```

两句都是原文，拼起来是废话。原因很直接：**抽取式没有归纳能力**，
它只会把句子按分数排出来，而「两句话之间什么关系」它不知道。

改成只从第一名那段取句后，答案干净了。代价是引用编号只有 `[1]` —— 但这才是诚实的：
规则版能做的事就是「把最相关那段的原话给你」，多句归纳是模型的活。

顺手发现第二个坑：如果第一名段落里有两句，第二句也要够贴近问题才收
（`scores[j] >= 0.6 * best`）。不收的话，「年假」这类问题会把段落里凑数的
「离职时未休年假按日工资折算补偿」也带上，答案是相关但跑题。

## 三、拒答的实测余量是负数

16 段语料，得分（本地哈希向量，512 维）：

| 问题 | 最高分 | 是否该答 |
| --- | ---: | --- |
| 一线城市住宿标准 | 0.384 | 是 |
| 回滚后先检查什么 | 0.378 | 是 |
| 退款多久到账 | 0.219 | 是 |
| 年假要提前几天申请 | 0.203 | 是 |
| 账号会被锁定多久 | 0.182 | 是 |
| 公司年会什么时候开 | 0.144 | 否 |
| **账号锁定多久** | **0.143** | **是，但被拒了** |
| 今天天气怎么样 | 0.131 | 否 |
| 怎么给猫剪指甲 | 0.061 | 否 |

阈值取 0.15：应答题 6 道里答对 5 道、误答 0；「账号锁定多久」（0.143）被挡在门外 ——
因为 `账号锁定` 和 `锁定账号` 的 bigram 顺序不同。

> **2026-11-03 用 `verify_scores.py` 复核，原来「余量只有 0.07」这个数是挑出来的。**
> 0.072 = 0.203（年假）− 0.131（今天天气），取了一对最宽松的。正确口径应当取
> **「最低的应答题」减去「最高的应拒题」**：
>
> | 口径 | 算法 | 值 |
> | --- | --- | ---: |
> | 原文的「0.07」 | 0.203（年假）− 0.131（天气） | +0.072 |
> | **真实最差间隔** | 0.143（账号锁定多久）− 0.144（公司年会） | **−0.001** |
>
> 负的意味着：**不存在任何一个阈值能同时答对这两道题**。压到 0.143 以下，
> 「公司年会什么时候开」被放行；抬到 0.144 以上，「账号锁定多久」被拒。
> 这不是调参能解决的，是分数空间本身没有判别力。
>
> 所以「阈值 0.15 可用」要降级成更诚实的说法：**在这份 16 段语料上，0.15 是
> 「宁拒勿答」策略下一个可接受的点**（误答 0、漏答 1），而不是「找到了好阈值」。

扫描表把这件事看得更清楚（`verify_scores.py` 的 [3]）：

| 阈值 | 答题数 | 召回 | 误答 | 漏答 |
| ---: | ---: | ---: | ---: | ---: |
| 0.00 | 9 | 6/6 = 1.000 | **3** | 0 |
| 0.13 | 8 | 6/6 = 1.000 | **2** | 0 |
| **0.15** | 5 | 5/6 = 0.833 | **0** | 1 |
| 0.20 | 4 | 4/6 = 0.667 | 0 | 2 |
| 0.30 | 2 | 2/6 = 0.333 | 0 | 4 |

**召回和误答是硬交换**：想全答对（召回 1.000），就得接受 2 道无关问题被回答；
想零误答，就得放弃 1 道真问题。中间没有两头兼顾的点 —— 因为那 0.001 的间隔是负的。

真上生产只有两条路：换 embedding 模型把间隔拉开，或者用 cross-encoder 重排
（Unit 26）把判定从「分数阈值」换成「成对打分」。

## 四、阈值必须在生成之前判

```python
if not hits or hits[0].score < threshold:
    return REFUSAL
answer = generate(prompt)
```

三个理由：

1. **可测**：`answer == REFUSAL` 是一条硬断言，模型自由发挥的「我不知道」不是。
2. **省钱**：拒答根本不调模型，一次都不花。
3. **不会误伤**：模型拿到 3 条无关片段时，最擅长的就是用它们编一段通顺的话。

自检里有一条专门反证这件事：把阈值调到 0，无关问题立刻「答」了起来 ——
说明拒答确实来自阈值判断，不是数据集碰巧。

## 五、trace 是这一章的第二个交付物

```sql
CREATE TABLE traces (
  trace_id, ts, question, mode, threshold, refused,
  hits, prompt, answer, usage, elapsed_ms
)
```

几个刻意的选择：

- **拒答也写 trace**，并且保留 hits。否则「为什么拒答」永远查不了。
- **存完整 prompt**：出问题第一件事是看真正发出去的东西。只存 question/answer 的日志，
  在你改了 prompt 模板之后完全无法复现。
- **usage 两种模式都填**：api 记 `prompt_tokens`，extractive 记字符数（粗估 token 用）。
  留空的话，后面算成本时这一段是黑洞。

## 六、API 路径只测解析，不真调

真调模型的自检有三个问题：要 key、要钱、结果不确定。所以边界切在 `parse_chat_response`：

```python
fake = {"choices": [{"message": {"content": "  提前 3 个工作日。[1]  "}}],
        "usage": {"prompt_tokens": 231, "completion_tokens": 12}}
```

`content` 取空、`choices` 为空、上游 4xx 这三种情况都单独测了一遍 ——
它们只有在真调一次失败时才会暴露，那时候你已经在排查业务问题了。

## 一句话总结

RAG 里最便宜也最容易被跳过的两件事 —— **判阈值拒答**和**存 trace** ——
恰好是它能不能上线的分界线；生成模型再强，也救不回「拿错资料硬答」。

## 面试追问

1. **「怎么防止模型在没有依据时乱答？」**
   → 别指望 prompt 里的「不知道就说不知道」。在生成前判检索分数，低于阈值直接返回固定话术，
   并把这个常量做成可断言的对象。模型只在「有依据」时出场，出场率才是可调的旋钮。

2. **「离线抽取式和真模型差在哪？」**
   → 抽取式只会摘原句，不能跨段归纳、不能做比较、不能改写语气。它的价值是给了一个
   **零成本、零幻觉的下界**：真模型的答案连这个下界都不如，就该怀疑 prompt 或检索，
   而不是继续换模型。

3. **「阈值 0.15 是怎么定的？」**
   → 扫出来的。16 段语料上相关的聚在 0.18~0.38，无关的聚在 0.06~0.14，取中间 0.15。
   但这个间隔只有 0.07，说明哈希向量的分数没有判别力 —— 所以我在笔记里写的是
   「拐点」而不是「最优值」，换 embedder 必须重扫。

4. **「为什么要存 prompt 而不是只存答案？」**
   → 因为 prompt 是你唯一能复现现场的东西。改了模板、换了 top_k、阈值调过一档，
   同一条 question 会得到完全不同的答案；只存 question/answer 的日志，事后无法归因。
