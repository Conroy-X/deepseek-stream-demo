## 一、为什么用 BM25 而不是"装个 bge-reranker"

这个仓库的约束是"clone 下来 uv sync 就能跑"。bge-reranker 要下载模型（几百 MB），
还要 torch，一个单元的依赖会压过整条链。

BM25 是真正的 CrossEncoder 吗？**不是**。它是字面模型，只是比"向量重叠"多了两件事：

- **IDF**：到处出现的词（"退款"）权重低，稀有词（"年终奖"）权重高
- **长度归一化 b**：长文档罚分，堆关键词立刻付代价

这两点让它在"长短差异大"的候选里明显更准，也让它足够便宜 —— 纯 Python，20 条候选不到 1ms。

接口故意和 CrossEncoder 对齐：

```python
rerank(query, candidates, top_k) -> list[Scored]
```

上真模型时只改这个函数的内部，上层不动。

## 二、短问题不提升，长问题提升

6 道题、`top_k=5`：

| 分组 | 向量 MRR | 重排 MRR |
| --- | ---: | ---: |
| 短问题 | 0.833 | 0.833 |
| 长问题 | 0.833 | **1.000** |
| 合计 | 0.833 | **0.917** |

短问题为什么不动：`密码多久换一次` 这种一句话一个意图，向量的整体相似度
已经足够准，重排只是复核。

长问题里那题最能说明问题：

```
账号密码输错几次会被锁，锁了找谁解锁？
向量首条：rl-3  「P1 事故 24 小时内出初稿，5 个工作日内完成复盘会」
重排首条：sc-2  「连续 5 次登录失败锁定账号 30 分钟，解锁需联系 IT 服务台」
```

向量把「24 小时内」「锁」这些字面噪声平均进了整体相似度；
BM25 抓的是「锁」「账号」「解锁」这三个高 IDF 词的集中命中，所以它对了。

**这就是"长 query 是双塔的弱项"的具体形态**：意图一多，向量被平均，排序就漂。

## 三、重排救不了堆砌页（本单元最重要的负结果）

语料里我放了一条 SEO 垃圾页：

```
退款 退款多久到账 退款流程 退款说明 退款查询 退款进度 退款到账 退款政策 退款客服 …
```

问「退款多久到账」：

| | 第 1 名 |
| --- | --- |
| 向量 | `sp-1`（堆砌页） |
| BM25 | `sp-1`（还是它） |

第一版我以为 BM25 能压住它 —— 有 IDF 有长度归一化嘛。结果没有：

1. 堆砌页把 query 的**每个 bigram** 都塞了一遍，tf 饱和之后分数依然很高
2. 页面里没有别的词稀释，`b=0.75` 的长度惩罚打不过这么高的词频

调 `b` 到 0.9 能压下去吗？试了，会连带把正常的短块也压得乱七八糟 ——
**参数调不动模型的能力边界。**

结论写进断言里了：`BM25 同样被堆砌页骗过（字面手段的边界）`。
这条断言不是"我接受了失败"，而是把已知局限固化下来，
防止后来有人看到 MRR 涨了就以为重排能解决一切。

## 四、一个容易忽略的实现细节

重排必须发生在**截断之前**：

```python
cands = recall(query, n=20)      # 召回 20
rerank(query, cands, top_k=5)    # 重排后取 5
```

如果召回就取 5，重排只是把 5 条重新排一遍，能救回的概率极低。
`recall_n` 和 `top_k` 是两个独立参数，别合成一个。

## 一句话总结

重排不是"更聪明的检索"，而是"更贵的排序"。
它只在**候选已经够好、但顺序不对**时有用；
召回没拿到的，重排永远变不出来 —— 这是两段式管线的边界，也是最容易吹过头的地方。

## 面试追问

1. **「什么时候该加重排？」**
   → 看两个信号：召回 recall@20 已经不错（说明答案在候选里），但 MRR 低（排序不对）。
   这时加重排收益最大。如果 recall@20 本身就差，先修召回，别浪费算力。

2. **「BM25 和向量检索怎么选？」**
   → 不是二选一。BM25 强在专有名词、编号、精确短语；向量强在语义近似。
   线上常见是**混合检索**：两路各取 20，用 RRF 融合，再重排。这就是 Day 76 的内容。

3. **「CrossEncoder 为什么慢？」**
   → 它要把 (query, doc) 拼成一对过一遍模型，N 条候选就是 N 次前向。
   双塔的 doc 向量可以离线预计算，所以能上索引。这就是"两段式"存在的根本原因。

4. **「MRR 和 nDCG 有什么区别？」**
   → MRR 只看第一个相关结果的位置，适合"只需要一条正确"的场景（问答）。
   nDCG 看整体排序质量，且支持多级相关性（很相关 / 有点相关）。
   有多个正确答案时用 nDCG，只有一个时 MRR 更直观。
