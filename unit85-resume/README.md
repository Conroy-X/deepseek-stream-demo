# Unit 85 · 简历：自动校验器

> 目标：**不替你写简历，替你查出「哪条会被筛掉」。**

---

## 一、四道硬检查

| 检查 | 为什么 | 不通过的后果 |
| --- | --- | --- |
| **无 PII** | 简历常在公开仓库/GitHub Pages | 手机号被爬走 |
| **动词开头** | 「负责/参与」显示不出你的贡献 | 面试官看不出你做了什么 |
| **量化结果** | 没数字等于没做 | 无法判断你的水平 |
| **条目数量** | 太少显得没项目 | 直接被筛 |

## 二、强弱动词对照

| 弱（避免） | 强（推荐） |
| --- | --- |
| 做了、负责、参与、帮忙、协助、跟进 | 构建、设计、优化、实现、搭建、开发、重构、主导、落地、抽象 |

## 三、量化的五种写法

```
提升 30% / 从 70% 提升到 92%      ← 百分比
性能提升 2x                        ← 倍数
P95 从 800ms 降到 120ms            ← 耗时
减少 3 个部署步骤                   ← 数量
覆盖 5 个业务场景                   ← 范围
```

## 四、怎么跑

```bash
cd ~/ai-journey/unit85-resume
uv sync
uv run python main.py            # 离线自检（验证校验器本身）

uv run uvicorn main:app --port 8085
curl "http://127.0.0.1:8085/audit/sample"       # 看内置示例的评分
curl -X POST "http://127.0.0.1:8085/audit" \
  --data-urlencode "text=你的简历内容" -G
```

## 五、完成标准

- [ ] `uv run python main.py` 自检全过
- [ ] 自己的简历跑一遍，score 达到 100 或问题清单为空
- [ ] 每条项目经历都能回答「我做了什么 + 结果多少」
- [ ] 确认简历里没有真实手机号/邮箱（公开仓库场景）

## 六、示例：三条项目经历的正确写法

```
- 构建企业知识库 RAG 系统，回答准确率从 70% 提升到 92%
- 设计 Agent 工具调用框架，支持 5 个工具，越权调用拦截率 100%
- 优化向量检索延迟，P95 从 800ms 降到 120ms
```

每条都是：**强动词 + 做了什么 + 量化结果**。

## 七、面试追问

**Q: 没有真实业务数据怎么量化？**
→ 用自己测的数据（离线评测集准确率、压测 P95、单元自检项数）。
「基于 30 条评测集，准确率 92%」比「效果很好」强一百倍。

**Q: 项目经历写几个？**
→ 2–3 个足够，宁少勿滥。每个都要能讲 10 分钟（背景/难点/方案/结果）。

**Q: 简历要不要放 GitHub 链接？**
→ 要。但要先确保仓库干净：有 README、有 .gitignore、没有密钥
（Unit 86 就是检查这个）。
